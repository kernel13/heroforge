## Deviations from the spec, all deliberate

1. **`limits` instead of `slowapi`.** slowapi applies limits by decorating an endpoint function,
   which cannot reach the register/login/verify/reset endpoints generated by `fastapi-users` —
   and the spec *requires* limits on exactly those. `limits` is slowapi's own engine, attachable
   as a FastAPI dependency. Same windows and storage.
2. **`skills.sheet_rows` column**, beyond the spec's table. The spec requires creating rows "to
   match the paper sheet's repeat count" (Craft 3, Knowledge 5, Perform 3, Profession 2); that
   count has to live somewhere, and reference data is where it belongs.
3. **`DerivedAbilities` / `DerivedSaves` are models with named fields**, not `dict[Ability, ...]`.
   A mapping schema generates a TypeScript index signature and the frontend loses the guarantee
   that every ability is present. `__getitem__` keeps engine-side indexing.
4. **URL reflects the open character** (`/characters/{id}`). Not in the spec, but reloading a
   sheet you have had open all evening should not land on the list.
5. **`VERIFICATION_REQUIRED` setting.** Defaults on, as the spec requires. Off only for local
   development and the e2e run, which have no mail server.

## Bugs found by running the stack that the tests did not catch

- **Debounce loop.** `useSheet` originally debounced `{draft, edits}` — a fresh object every
  render, so the derive effect re-fired forever and each re-render restarted the 2 s save timer,
  which then never completed. Symptom: `/api/derive` every 250 ms, zero PATCHes. Fixed by
  debouncing the edit counter and reading the draft through a ref. The Vitest suite passed with
  the bug present; fake timers do not advance React's re-render chain the same way.
- **`VERIFICATION_REQUIRED` half-applied** — reached the login router only, so with it off a user
  could log in and then got 403 on every request.
- **`psycopg` was dev-only** but Alembic needs it at container start. Now a runtime dependency.
- **Backup command as a folded YAML block** — YAML joins the lines with spaces, turning the shell
  pipeline into a syntax error. Now `docker/backup.sh`.
- **sqladmin auth was both broken and wide open.** `SuperuserOnly.authenticate` called the route
  dependency by hand; nothing resolves `Depends` outside a request, so `user` was bound to the
  `Request`. With verification on it raised `AttributeError` and refused *everyone*, superusers
  included; with verification off the check short-circuited before touching the attribute,
  returned a truthy request, and **admitted anonymous visitors**. Every other test builds the app
  with `mount_reference_admin=False`, so nothing exercised it. `tests/test_admin.py` now does,
  and both failures were confirmed to reproduce against the original code.
- **App logger had no handler** under uvicorn, so with no SMTP configured the verification link
  was silently discarded and a fresh deployment could never activate its first account.
  `src/heroforge/logging.py` fixes it; unsent mail logs at WARNING.

## Golden character (test anchor)

Bramwell Tosscobble, gnome Fighter 5 / Rogue 2. Small (ac_size +1, grapple_size_modifier −4),
STR 13 DEX 16 CON 14 (temp 16) INT 12 WIS 10 CHA 8, full plate (−6) + heavy steel shield (−2),
carried weight exactly 100 lb = the medium limit for STR 13.
AC 23 / touch 13 / flat-footed 22, initiative 7, grapple 3, ACP −8, Fort 8 / Ref 7 / Will 1,
Swim −10, Climb 3, Tumble −2 (3.5 ranks floor to 3).

## Invariants pinned by tests

- `flat_footed_ac = armor_class - max(effective_dex_bonus, 0)`.
- cross-class `max_ranks = (level + 3) / 2` stays a half-integer; compared against *unfloored* ranks.
- ACP stored non-positive; the engine ADDS it; Swim adds it twice.
- `grapple_size_modifier` is a stored column, never derived from `size`.
- Load category boundaries inclusive at the top.
- The engine never raises; violations become `DerivedSheet.warnings`.
- `ranks` serialises as a decimal string; "0" and "0.0" are the same value.
- The two debounces stay separate (250 ms derive / 2 s save).

## Licensing posture

The sheet's **structure** (which fields exist, how they combine) is Open Game Content and is
reproduced. The published sheet's **design** — black-bar headings, WotC typography, trade dress,
the "Dungeons & Dragons" name — is not, and is deliberately absent. `OGL.txt` ships the full
licence plus a Section 15 declaration, and is served at `/OGL.txt`.

Naming: "HeroForge" still collides with heroforge.com. The UI says "Character sheet manager"
throughout; a real product name is still to be chosen. The repo directory name is not a problem.
